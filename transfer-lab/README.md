# Transfer Lab · 足球转会实验室

独立的中文足球管理网页游戏，已接入社团首页导航。静态文件即可运行，不需要账户、API 密钥或数据库。

## 启动

在项目根目录运行 `npm run dev`，访问 http://localhost:4173/transfer-lab/ 。若端口已被现有网站占用，可直接使用现有服务，或执行 `PORT=4174 npm run dev`。不要用 `file://` 打开页面，因为浏览器需要加载模块和 JSON 数据。

## 数据与边界

快照日期为 **2026-09-27**。英超球员数据来自官方 FPL；英超八队的常规位置由 ESPN 名单补充，按唯一出生日期匹配，未匹配时回退 FPL 分类。西甲三队名单和两联赛当前积分榜来自 ESPN。原始响应保存在 `data/raw/`，来源 URL 存在 `data/snapshot.json` 的 `sources` 中。

营收基线为 Deloitte Football Money League 2026 的 **2024/25** 数据，通过 Wikipedia 汇总表读取，证据摘录在 `data/finance-evidence.json`。未来营收增长、运营成本、存量摊销、工资和转会预算均是公开列明的游戏假设，非俱乐部官方预算；没有把 FPL 游戏价格当成现实转会费。

球员能力/估值、球队先验、目标、伤病折损及比赛模型尚未历史回测校准。模拟使用当前名单开启假想夏窗与新赛季，现实已经发生的比赛不带入积分，仅作为小幅实力调整。背景球队不主动交易；西甲其余球队只使用球队级实力。没有欧战/杯赛、完整注册规则、真实合同和真实 PSR 判定。同分规则统一简化为积分、净胜球、进球数、固定球队 ID。

页面「数据与规则」列明全部评分公式、估算与限制。

## 更新与验证

- `npm run data:refresh`：从来源重新下载并重建快照，校验赛季一致、联赛队数和 11 队名单完整性。失败不覆盖可用快照。财政基线不自动刷新，须核对新报告后更新。
- `node transfer-lab/data/update-data.mjs --offline`：从保留的原始响应重建本次初始快照。
- `npm test`：使用 Node 内置测试工具，验证赛程完整性、11 队可玩性、买卖账务、谈判失败、预算边界、阵容限制、模拟守恒、随机种子可复现和存档校验。

核心代码：`engine.mjs` 为纯游戏逻辑，`app.mjs` 为界面，`style.css` 为响应式样式。没有生产依赖，测试也无需安装包。

## 转会谈判机制

每名球员都有隐藏的雄心、忠诚度、偏好联赛、剩余合同年限和少量解约金信息。卖方底线会根据阵容深度、现实排名、同联赛竞争、财政压力和球员合同变化；球员则会比较薪资、合同长度、买方竞争力和联赛偏好。报价达到底线也只会提高概率，不能保证签约。每个新档使用自己的种子，所以同样的报价在不同新档可能有不同结果，同时同一存档可复盘。

低报价会更容易收到还价；如果球员倾向离队但卖方拒绝，可能触发“罢训”事件，并在赛季模拟中造成轻微实力损失。出售球员时，不同买家的需求、预算和市场情绪会生成不同报价与兴趣度，拒绝后不消耗现金但会消耗 1 天。
